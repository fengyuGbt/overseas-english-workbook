# 邮件03 · 第一封项目周报（Weekly Progress Report）

> 场景：Northwind 数据管道项目第 1 周结束，给 PM Tom 发第一封英文周报
> 对应听力06：Tom 要求每周三 9am ET 周会 + weekly progress reports in English

## 场景任务

你是接单开发者 FF，项目进行到第 1 周。给 Tom 写一封周报邮件，80-120 词，包含 4 块：本周进展 / 下周计划 / 风险问题 / 需要的支持。

## 用户习作（原文）

```
Subject: Weekly Progress Report — Data Pipeline Project (Week 1)
Hi Tom,
**Progress this week:**
- Set up the GitHub repo(Github:fengyuGbt/datapipeline) with main + feature branches
- The project is on track. Milestone 1 (data ingestion module)
```

## 逐句批改

| # | 原文 | 问题 | 修正 |
|---|---|---|---|
| 1 | repo(Github:...) | 括号前缺空格；仓库地址写法不规范 | `repo (github.com/fengyuGbt/datapipeline)` |
| 2 | due **on** next Friday | on + next Friday 冗余（on 只接具体日） | `due next Friday` |
| 3 | **i**nterview two candidates | 清单项首字母统一大写 | `Interview two candidates` |
| 4 | for **backend team** | team 前缺冠词 | `for the backend team` |
| 5 | data access is unstable, have to... | 逗号连接两完整句（comma splice）+ 后半句缺主语 | `Data access is unstable, so we have to change the way we pull data.` |
| 6 | confirm **to approve** | 双重动词；语义应为"批准/提供" | `Could you please share the data feed credentials with us by next Monday?` |
| 7 | credentials **to your team** | 介词错；凭据是"给我们的" | `credentials for our team` |

**错数：6**（语法搭配 2 + 句子结构 3 + 格式规范 1）

**逻辑问题（不算语法错但必须改）**：Risks 里说"等对方给凭据"，Support needed 里却说"请您批准凭据给您的团队"——两头矛盾。**Risks 和 Support needed 必须对应**：等什么，就请对方给什么。

## 风险写法四要素（内容层重点）

风险不能只"报忧"——每条风险要带**状态**，给的是决策信息：卡没卡、谁来解、什么时候解。

**状态三档：**

| 状态 | 含义 | 例句 |
|---|---|---|
| Open | 未解决，需要对方支援 | Open — waiting for the data feed credentials, which blocks the ETL work. Please share them by Wednesday. |
| In progress | 处理中，自己在解决 | In progress — data access has been unstable; we are switching to a more reliable source and expect to resolve it by Friday. |
| Resolved | 已解决，闭环 | Resolved — the timeout issue in the batch job was fixed yesterday.（听力02 原句） |

**四件套**：状态 + 描述 + 影响 + 下一步/需要谁 by 日期。

## 本课必记

1. **due 三兄弟**：due **in** + 时间段（3 weeks 后到期）/ due **on** + 具体日（Friday、the 28th）/ due **by** + 截止日。**on next Friday 是冗余，去掉 on**。
2. **凭据给谁用 for**：credentials **for our team**（给我们的凭据），不是 to。
3. **confirm 用法**：`confirm that + 从句` 或直接动词（approve / share），**不要 confirm to do**。
4. **"获取数据的方式"**：the way **we pull data / we get data**（定语从句），比 the way to get data 更地道。
5. **周报逻辑闭环**：Risks（等什么）→ Support needed（请对方做什么），一一对应。
6. **清单格式**：列表项首字母统一大写；逗号不能连接两个完整句子（用 and / so 或分号）。
